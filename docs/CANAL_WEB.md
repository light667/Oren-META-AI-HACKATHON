# Canal web et page publique de chat (2026-10-30)

Adaptateur `src/channels/web` (entrée `handleWebMessage`, confirmation structurée `confirmWebOrder`, humain `requestWebHuman`) au-dessus de `core/handleMessage`, sans logique métier dans le canal ; routes SSE sous `src/app/api/chat/[slug]` (message en flux, confirmation, humain).
Page publique `/[slug]` : chat mobile d'abord, réponse affichée en continu (événements SSE), session anonyme en `localStorage`, mention « Vous parlez à un assistant IA », boutons « Parler à un humain » et « Écrire au restaurant sur WhatsApp » (`wa.me` sur `config.phone`, sans API), PWA installable (manifeste + icônes).
Commande : la carte de récapitulatif (calculée en code) demande nom et téléphone (customers, `phone_verified_at` vide) et le mode de paiement (livraison ou sur place) ; le bouton « Je confirme » envoie l'action structurée avec le jeton — chemin principal, sans interprétation de texte. L'accord texte a été durci : « oui », « ok », « d'accord », « c'est bon », « je valide », « vas-y », « je confirme » acceptés ; toute question ou modification (« oui mais… », « et la boisson ? ») refusée, cas ajoutés aux tests.
Le patron télécharge le QR code de son lien depuis « Mon entreprise ». Preuve de bout en bout le 2026-10-30, contre le vrai modèle et la base distante : horaires répondus, commande 2 attiéké + 1 jus livrés à Agoè = 5000 FCFA confirmée en base via le bouton (données de test ensuite supprimées, téléphone démo aligné sur le seed).
Pour l'essayer : ouvrir `/chez-chef-t` sur un téléphone, demander les horaires, commander deux plats, confirmer avec le bouton ; la commande apparaît dans `orders` (vérifiable par `npm run check:remote` et l'écran Commandes du patron).
