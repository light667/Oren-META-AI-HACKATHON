# Fix lien e-mail /auth/callback (2026-11-04)

Cause : `next.config.ts` forçait `output: "export"` (export 100 % statique), incompatible avec `/auth/callback` et toutes les routes API (session par cookies, échange de code Supabase) — erreur Runtime en dev, et en prod la route n'existait pas, d'où le retour sur l'accueil.
Correctif : retrait de `output: "export"` (app serveur Vercel conservée), nettoyage de l'export du config, et callback durci dans [route.ts](/src/app/auth/callback/route.ts) : formats `?code=` (PKCE) **et** `?token_hash=&type=` (modèle e-mail), `?error=` géré, tout échec → `/connexion?erreur=lien`, jamais l'accueil ; succès → `/app/commandes` si membre, `/bienvenue` sinon.
Test de régression : [route.test.ts](/src/app/auth/callback/route.test.ts) (7 tests, dont l'interdiction de retomber en export statique). Vérifié : test ciblé 7/7, `npm test` 168 passés, `npm run build` OK avec `ƒ /auth/callback` (dynamique), typecheck et lint OK.
Action manuelle obligatoire côté Supabase (dashboard, projet de prod) : Auth > URL Configuration > **Site URL** = domaine de prod, et **Redirect URLs** doit contenir `https://<domaine-prod>/auth/callback` (plus `http://localhost:3000/auth/callback` en dev). Si l'URL n'est pas dans cette liste, Supabase ignore `emailRedirectTo` et renvoie vers la Site URL, donc l'accueil — aucun code ne peut corriger ça.
Comment essayer : redéployer sur Vercel, s'inscrire sur `/inscription`, cliquer le lien reçu → arrivée sur `/bienvenue` (nouveau compte) ou `/app/commandes` (compte existant), lien expiré → `/connexion` avec message d'erreur.
